## Priority failure cases to reproduce

| Finding | Affected source | Needed test and expected outcome |
| --- | --- | --- |
| Opening an orphan run can crash the trail. `trail_run()` returns `site: null` if its survey cannot be read; the component accesses `run.site.status` and `run.site.builder` unconditionally. | [API `trail_run`](../../services/incident-api/backstage_api/pivot.py), lines 452–473; [TrailConsole](../../apps/web/src/diagnostics/TrailConsole.tsx), lines 517–519; `TrailRunResponse` type in [client](../../apps/web/src/api/pivot.ts). | Return a valid ledger run with missing survey, then open it in the UI. Verify the timeline remains available and site absence is reported without an exception. Repeat for a transient survey-provider failure. |
| Interest-filtered trends use different populations. Surveys and interactions filter by the chosen interest, while the ledger query filters only time and source. Its builds, decisions, builders and commit modes therefore include other interests. | API `Pivot.trends()`, lines 336–365. | Seed two surveys with distinct interests, associated runs/decisions and the same source. Filter to one interest and verify every agent chart includes only that cohort. Keep an unfiltered control query. |
| Stored commit links are not restricted to the intended GitHub repository. Backend forwards the commit object/site URL, and `safeUrl()` accepts any HTTP or HTTPS URL. Existing trace URL creation separately uses the constrained helper. | API `trail_item()`, lines 406–413, attendee `SITE_FIELDS`; TrailConsole `safeUrl()`, lines 154–155 and commit link rendering. | Supply an HTTP URL, arbitrary HTTPS host, userinfo URL, lookalike GitHub host, wrong repository and mismatched SHA. Only an approved repository's HTTPS commit URL with the expected SHA should become a clickable commit link. Keep malicious highlight fragments as text; existing `renderHighlight()` already avoids raw HTML. |
| The hourly budget is a count-then-write check without a concurrency reservation or explicit refresh. Concurrent requests can all observe headroom, and a just-created document may remain invisible to the next count until Elasticsearch refreshes. | API `create_survey()`, lines 240–270. | With a cap of one, issue concurrent survey requests and a sequential pair before normal refresh. Assert at most one build is accepted and excess requests receive 429. Include an existing prior-hour document and a restart case. |
| Partial Elasticsearch responses are treated as complete. `Pivot.search()` returns the response without checking `timed_out` or failed shards. Recommendations, charts and trail may present incomplete data without degradation. | API `Pivot.search()`, lines 166–170. | Fake `timed_out: true`, nonzero `_shards.failed`, and a healthy response with zero hits. Partial responses should produce explicit unavailability/degradation, while a verified empty result remains a valid empty result. |

## Confirmed blocker: accepted ledger write times out (23:39 UTC)

**Luke / Ahmed:** the worker transport timeout is5s and every ledger create waits for refresh. Real isolated reproduction at production settings: `run_tz34ug26aqyo:0004` failed with `ConnectionTimeout` at5007ms, yet a realtime GET returned that exact seq4 plan event with outcome ok. The worker then stored error seq5 and marked the survey failed. Shareddemo latest5 runs show the same ledger_write_failed symptom; shareddata was read-only during this investigation.

- Minimal immediate change: raise `services/agent-workers/agent_workers/__main__.py` Elasticsearch request_timeout above the observed refresh interval (15s margin;10s already passed the orchestrator's full15-check smoke). Keep max_retries0 to avoid blind writes.
- Correct recovery: on ambiguous ledger acknowledgement, realtime GET and compare the deterministic event before treating it as failed. Claim and owned_update also use refresh=wait_for and need the same deadline audit.
- Better latency: intermediate ledger creates should not each force a refresh wait; establish searchable visibility at the necessary boundary. Preserve committed-event ordering.
- Evidence: isolatedprefix backstage-qa-pivot-integrated only; simulator attendee att_gqioeea3tiv2, run run_tz34ug26aqyo. Previous writes took4872ms and5011ms. The five-second configuration failed in29s;10s configuration completed a4209-byte template with10 events. This is observed accepted-write/unknown-ack behavior, not inference from a fake client.
